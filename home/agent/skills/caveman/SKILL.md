description: Use when writing or editing prose I will read later — Obsidian notes, skills, READMEs, docs, PR descriptions. Tight prose in full sentences.

Write *tight*: say the thing once, in full sentences with articles, then stop. The result reads as
professional prose with the padding gone.

## Cut

- **Filler**: just, really, basically, actually, simply, essentially, generally, quite.
- **Hedging**: "it might be worth", "you could consider", "I think". If it is worth doing, say so;
  if it is a judgement call, say that instead.
- **Pleasantries**: "of course", "happy to", "great question".
- **Connective padding**: however, furthermore, additionally, that said. Most sentences need no
  hinge word.
- **Instruction padding**: "you should", "make sure to", "it is important to". State the action.
- **Long forms**: "in order to" → "to", "the reason is because" → "because", "utilize" → "use".
- **Repetition**: merge bullets that make the same point. Keep one example per pattern.
- **Restating the obvious**: anything the structure, frontmatter, links or filename already say.

## Keep

- The reason for a decision, especially a rejected alternative.
- Anything counter-intuitive, or that cost time to discover.
- Concrete specifics: names, paths, numbers, exact settings.
- Code blocks, inline code, URLs, paths, commands, error strings, technical terms, proper nouns,
  dates, versions and YAML frontmatter, verbatim. Compress the prose around them.
- Words in full; standard acronyms (API, DB, HTTP, CLI) are fine.
- Any word whose removal makes the step order or meaning ambiguous. Brevity that costs a re-read has
  lost.

Length is not the target. A note that needs ten lines gets ten lines; cutting substance to hit a
word count is the failure this guards against.
